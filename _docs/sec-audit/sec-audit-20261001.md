# Bezpečnostní audit — elvisek.cz (šablona ElvisEK 0.4.4, plugin ElvisEK Core 0.4.4)

Datum: 2026-10-01 · Rozsah: `theme/elvisek`, `plugins/elvisek-core`, `mu-plugins/elvisek-dev-tools.php`, `tools/*.py`, `.github/workflows/release.yml`, `dev/` a provozní prostředí (produkční webroot přes FTP, veřejné HTTP odpovědi, práce s tajnými údaji).

### Manažerské shrnutí

Kód šablony a pluginu je celkově v dobrém stavu: administrátorské akce mají nonce a kontrolu oprávnění, výstupy jsou escapované, SQL dotazy jsou parametrizované nebo pracují jen s konstantami, aktualizace se stahují jen z pevně daného repozitáře přes HTTPS. Nalezeny byly **3 nálezy STŘEDNÍ závažnosti** (0 kritických, 0 vysokých): (1) uložené XSS přes JSON-LD v `<head>` (únik ze `<script>` díky `JSON_UNESCAPED_SLASHES` a dekódování entit), které umožňuje eskalaci z role Redaktor na administrátora, (2) tajné údaje a produkční záloha v prostém textu ve složce synchronizované s iCloudem a FTP bez TLS, (3) dodavatelský řetězec release pipeline (akce třetí strany na měnitelném tagu s právem zápisu, bez ověření integrity balíčku). **Jako první opravit nález č. 1** – jde o jednu řádku kódu a uzavírá cestu k převzetí administrace.

### Nálezy

**[STŘEDNÍ] Uložené XSS v JSON-LD (únik ze `<script>` v hlavičce článku)**

- **Soubor / umístění**: `theme/elvisek/inc/seo.php`, ř. 22 (`ek_meta_description`), ř. 9 (`ek_plain_title`), ř. 117 (výpis JSON-LD)
- **Problém**: Popis článku se bere z obsahu (nebo úryvku), odstraní se tagy a pak se **dekódují HTML entity** – text `&lt;/script&gt;` se tím změní na doslovné `</script>`. Stejně titulek. Výsledek se vloží do `<script type="application/ld+json">` přes `wp_json_encode(..., JSON_UNESCAPED_SLASHES)`, takže se lomítko neescapuje a řetězec `</script>` ukončí skriptový blok. Následující text se vykoná jako HTML/JS v `<head>` každé stránky článku – pro návštěvníky i přihlášeného administrátora.
- **Cesta útoku**:
  1. Útočník má účet s rolí Redaktor (Author) – např. únikem hesla aplikace uživatele `claude` (viz nález 2) nebo jiného autora.
  2. Vytvoří/upraví článek, jehož první odstavec obsahuje text `&lt;/script&gt;&lt;script&gt;fetch('/wp-admin/user-new.php')…&lt;/script&gt;` (editor to uloží jako entity – pro autora bez `unfiltered_html` je to legální text). Alternativně stejný text v titulku.
  3. Administrátor otevře náhled nebo publikovaný článek → skript běží v jeho relaci, načte nonce a vytvoří nového administrátora / nahraje plugin → spuštění kódu na serveru.
  4. Stačí i neúmysl: článek „o HTML“, který na začátku zmíní `</script>`, rozbije stránku.
- **Důkaz**:
  ```php
  // seo.php:15-22
  $text = has_excerpt( $post ) ? $post->post_excerpt : $post->post_content;
  $text = wp_strip_all_tags( strip_shortcodes( excerpt_remove_blocks( $text ) ) );
  $text = trim( preg_replace( '/\s+/u', ' ', html_entity_decode( $text, ENT_QUOTES, 'UTF-8' ) ) );
  // seo.php:104-105, 117
  'headline'    => ek_plain_title(),
  'description' => $desc,
  echo '<script type="application/ld+json">' . wp_json_encode( $schema, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE ) . "</script>\n";
  ```
- **Doporučení**: Kódovat znaky `<`, `>`, `&` v JSON (JSON zůstane validní, prohlížeč nemůže blok ukončit):
  ```php
  echo '<script type="application/ld+json">'
     . wp_json_encode( $schema, JSON_UNESCAPED_UNICODE | JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT )
     . "</script>\n";
  ```
  (Meta tagy `og:*`/`twitter:*` jsou v pořádku – procházejí `esc_attr`.)

**[STŘEDNÍ] Tajné údaje a produkční záloha v prostém textu ve složce synchronizované s iCloudem; FTP bez TLS**

- **Soubor / umístění**: `ctime.txt` (kořen projektu), `backup-2026-09-30/files/www/wp-config.php`, `backup-2026-09-30/db/*.sql.gz`, pomocný FTP klient (`~/work/ftpc.py` v pracovní VM, ř. 9–11)
- **Problém**:
  - `ctime.txt` obsahuje v prostém textu přístup k FTP (plný zápis do webrootu), k databázi (uživatel s plnými právy) a heslo aplikace WordPressu. Složka `~/Documents/Projekty/…` je synchronizovaná s iCloud Drive (soubory byly při práci „jen v cloudu“ a musely se stahovat), takže tajemství leží i mimo Mac. `.gitignore` chrání jen před GitHubem.
  - Záloha obsahuje produkční `wp-config.php` (heslo k DB, **autentizační klíče a soli**) a kompletní dump DB (hashe hesel, e-maily komentujících).
  - FTP se při práci připojuje bez šifrování: pokus o FTPS selhal a klient spadl zpět na čisté FTP, takže heslo k FTP šlo po síti v prostém textu.
- **Cesta útoku**:
  1. Kompromitace Apple ID / iCloudu, sdílení složky, malware se synchronizací, nebo odposlech FTP na nedůvěryhodné síti.
  2. Útočník získá FTP heslo → nahraje PHP soubor do webrootu → plné ovládnutí webu. Se solemi z `wp-config.php` může navíc padělat přihlašovací cookies, s DB heslem číst/měnit databázi (pokud je dostupná).
- **Důkaz**:
  ```python
  # ftpc.py
  f=ftplib.FTP_TLS(host,timeout=60); f.login(user,pw); f.prot_p(); return f
  except Exception as e:
      print('FTPS fail',e); f=ftplib.FTP(host,timeout=60); f.login(user,pw); return f   # fallback na nešifrované FTP
  ```
  Výstup při připojení: `502-Auth command is not supported.`
- **Doporučení**:
  1. Přesunout tajemství z `ctime.txt` do Klíčenky macOS / správce hesel (např. `security add-generic-password …`, skripty je načtou přes `security find-generic-password -w`).
  2. Zálohu s `wp-config.php` a DB uložit mimo iCloud nebo do šifrovaného obrazu disku (Disková utilita → šifrovaný .dmg), případně zašifrovat (`age`/`gpg`).
  3. **Rotovat** FTP heslo, DB heslo a soli (`wp-config.php` → nové klíče z https://api.wordpress.org/secret-key/1.1/salt/) – soli a heslo leží v nechráněné kopii.
  4. FTP používat jen přes FTPS (z Macu, kde to síť nepřeruší) a nástroje upravit tak, aby **nikdy nepadaly zpět** na nešifrované FTP; FTP účet ve WEDOS vypínat, když se nepoužívá.

**[STŘEDNÍ] Dodavatelský řetězec release: akce třetí strany na měnitelném tagu, balíček bez ověření integrity**

- **Soubor / umístění**: `.github/workflows/release.yml`, ř. 10–11 a 38; `plugins/elvisek-core/inc/core.php`, ř. 247–276; `theme/elvisek/inc/updater.php`
- **Problém**: Workflow s oprávněním `contents: write` spouští `softprops/action-gh-release@v2` (akce třetí strany) přes měnitelný tag. Pokud je akce kompromitována (obdoba incidentu `tj-actions/changed-files`, CVE-2025-30066), může podvrhnout obsah `elvisek-core.zip`/`elvisek.zip` v releasu. WordPress pak aktualizaci nainstaluje z `browser_download_url` bez kontroly otisku či podpisu – kód poběží na produkci s plnými právy.
- **Cesta útoku**:
  1. Útočník převezme repozitář akce nebo přesune tag `v2` na škodlivý commit.
  2. Při příštím `git push --follow-tags` akce nahraje do releasu upravený ZIP (má token s právem zápisu).
  3. Administrátor klikne v Nástěnce na „Aktualizovat“ → backdoor v pluginu/šabloně.
- **Důkaz**:
  ```yaml
  permissions:
    contents: write
  ...
      - uses: actions/checkout@v4
  ...
        uses: softprops/action-gh-release@v2
  ```
- **Doporučení**: Odstranit závislost na akci třetí strany – `gh` CLI je na runnerech předinstalované:
  ```yaml
      - uses: actions/checkout@<plný-SHA-commitu>   # v4, připnout na SHA
      - name: GitHub Release
        env: { GH_TOKEN: ${{ github.token }} }
        run: gh release create "$GITHUB_REF_NAME" elvisek.zip elvisek-core.zip --generate-notes
  ```
  Dále: zapnout 2FA/passkey na GitHub účtu, chránit tagy `v*` (Settings → Rules → Tag protection) a volitelně do releasu přidávat `SHA256SUMS` a v updateru kontrolovat otisk.

### Shrnutí doporučení

1. **Opravit JSON-LD** v `seo.php` (`JSON_HEX_TAG | JSON_HEX_AMP …` místo `JSON_UNESCAPED_SLASHES`) – uzavře eskalaci Redaktor → administrátor.
2. **Rotovat tajemství** (FTP, DB, soli ve `wp-config.php`, heslo aplikace `claude`) a přesunout je z `ctime.txt` do Klíčenky; zálohy s `wp-config.php`/DB mimo iCloud nebo šifrovaně.
3. **Ověřit a případně povýšit PHP na produkci** (8.1 je bez oprav) na 8.4/8.5.
4. **Zabezpečit release pipeline**: `gh release create` místo akce třetí strany, `checkout` připnout na SHA, 2FA na GitHubu, ochrana tagů `v*`.
5. **FTP jen šifrovaně** (FTPS, bez fallbacku) a FTP účet držet vypnutý, když se nepoužívá.

*Ověřeno bez nálezu (pro úplnost):* nonce + `manage_options` u všech akcí Údržby webu a rubrik; parametrizované SQL / konstanty; escapování výstupů (TOC, vyhledávání, komentáře, reporty); anti-spam komentářů s podpisem `wp_hash` a `hash_equals`; login limiter používá skutečnou IP klienta (v logu různé veřejné IP); updater stahuje jen z pevného repozitáře přes HTTPS; `/llms.txt` jako `text/plain`; dev-tools mu-plugin je aktivní jen v prostředí `local`; produkční soli se liší od `dev/wp-config.php`; staré zálohy BackupWordPress už na serveru nejsou.
